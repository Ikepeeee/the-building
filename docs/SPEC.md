# The Building 仕様書（チーム共通の契約）

ニンテンドー「ザ・タワー」（SimTower）にインスパイアされた**オリジナル**のビル経営シミュレーション。
本家の名称・ロゴ・画像・音楽は使わない。絵はすべて Canvas でプロシージャルに描く（外部画像ファイルなし）。

- 静的ファイルのみで動く SPA（GitHub Pages にそのまま置ける）。ビルド工程なし、依存ライブラリなし。
- ES Modules（`<script type="module">`）。import は相対パスで、拡張子 `.js` を付ける。
- セーブは `localStorage`（キーは `SAVE_KEY` を基準にする）。
- PC（マウス・キーボード）とスマホ（タッチ・縦横画面）の両方に対応する。
- UI の文言は日本語。

## ファイル構成と担当

| パス | 担当 | 内容 |
|---|---|---|
| `js/sim/constants.js` | リード（数値バランスの調整のみ sim 担当も可） | 共有定数・施設定義・座標変換 |
| `js/sim/tower.js` | sim | `export class Tower`（シミュレーション本体、DOM 非依存） |
| `js/sim/events.js` 他 `js/sim/*.js` | sim | 事件（爆弾・火災・ゴキブリ・苦情・VIP・結婚式） |
| `tests/*.mjs` | sim | Node で動く自動テスト（`node tests/sim.test.mjs`） |
| `js/render/*.js` | render | `export class Renderer`、ピクセルアート描画 |
| `index.html`, `css/*`, `js/main.js`, `js/ui/*.js` | ui | 画面・入力・ゲームループ・セーブ・効果音 |
| `README.md` | ui | 遊び方と GitHub Pages への公開手順 |

**自分の担当外のファイルは編集しない。** 他担当への要望は、最終報告の中に書くこと。

## 座標系

- マス x: 0〜`W-1`、フロア f: `MIN_F`(-10, B10F) 〜 `MAX_F`(99, 100F)。f=0 が 1F、地面は 1F の下端。
- ワールドpx: `wx = x*TILE_W`、フロア f の上端は `wy = -(f+1)*FLOOR_H`、下端は `-f*FLOOR_H`。
- カメラ `cam = {x, y, zoom}`。持ち主は UI。変換関数は constants.js にある。

## ゲーム内容（本家準拠）

### 時間
- 1日 = 1440 分。`time` は開始からの通算分。0日目は月曜の 06:00 に始まる。曜日は `WEEK[day % 7]`（5・6 が土日）。
- 等倍で 1 実秒 = 6 ゲーム分。速度は `SPEEDS`。

### 建設ルール
- 地上の f>0 に建てるには、真下（f-1）の同じマスに何か（フロア・施設）が必要。地下の f<0 は真上（f+1）に何か必要。f=0 は常に建てられる。
- 施設は空マスまたは空きフロアの上に置ける。空マスに置いた場合はフロア代（1マス $500）を加算する。
- `only` 制約: lobby は `LOBBY_FLOORS` の階のみ、cathedral は f=99 のみ、recycling と metro は地下のみ（h フロアすべてが f<0）、`aboveGround` は f>=0。
- h>1 の施設は f〜f+h-1 を占有する。支えの判定は一番下の段（地下施設は一番上の段）で行う。
- 階段とエスカレーターは f に置き、f と f+1 をつなぐ。f+1 の同じマスにもフロアが必要。
- エレベーターは縦にドラッグして範囲 lo〜hi を決める。通常のエレベーターは最大30フロア。急行エレベーターはロビー階と地下階にだけ停止する。
- 撤去: 施設を撤去すると空きフロアに戻る。空きフロアの撤去は、それが支えている上下の構造がなければできる。返金はない。

### 人の流れ
- 人はロビー（1F）と地下鉄駅から出入りする。経路はフロアを節点としたダイクストラ法で求め、手段は通常・急行エレベーター、階段、エスカレーター。徒歩は 1分あたり 2.5 マス。
- ストレス: エレベーター待ちが3分を超えると増え、階段でも増える。移動のたびに 0 から数える。色は 0〜29 が黒、30〜59 がピンク、60 以上が赤。
- 評価: 目的地に着いたときのストレスを施設ごとに平均する。`evalLevel(o)` は `'good'`（<20）、`'fair'`（<45）、`'bad'` のいずれか。テナントは bad が2日続くと退去する。
- オフィス: 平日 7〜9時に出社、昼に 6割が飲食店へ、17〜19時に退社。平日の正午に賃料が入る。
- マンション: 入居時に販売収入。平日は 7割が通勤・通学で外出し、休日は買い物や外食に出る。
- ホテル: 16時に予約、16〜20時にチェックイン、翌 7〜10時にチェックアウトで宿泊料。チェックアウト後は「要清掃」になり、ハウスキーピングが清掃するまで次の予約が入らない。
- 商業施設: 営業時間中、外部客が人口に比例して来店する。客1人ごとに売上。
- 騒音: マンションまたはホテルの同じ階・4マス以内に飲食・映画館・パーティーホールがあると、評価が悪化し苦情の原因になる。
- 維持費: 毎日0時に、エレベーターのカゴ1台につき $600 などを支払う。

### ★評価
| ★ | 条件 | 解放（主なもの） |
|---|---|---|
| 1 | 開始 | フロア、ロビー、階段、エレベーター、オフィス、マンション、ファストフード |
| 2 | 人口 300 | ホテル（シングル・ツイン）、レストラン、ショップ、エスカレーター、警備室、ハウスキーピング |
| 3 | 人口 1000 ＋ 警備室 | 急行エレベーター、スイート、映画館、パーティーホール、医療センター、リサイクルセンター |
| 4 | 人口 3000 ＋ 医療センター ＋ リサイクルセンター ＋ VIP の高評価 | 地下鉄駅 |
| 5 | 人口 6000 ＋ 地下鉄駅 | 大聖堂 |
| TOWER | ★5 ＋ 100F の大聖堂で結婚式が成功 | エンディング |

### 事件（events）
- **テロリストの爆破予告**: ★2 以上でまれに発生する。`prompt` で身代金（人口に応じて $10万〜$100万）を要求される。払えば終わり。拒否すると、ランダムなフロアに爆弾が仕掛けられ、制限時間は3時間。警備室があれば警備員が1フロアずつ捜索し（警備室が多いほど速い）、見つかれば解除。見つからなければ爆発し、爆心の ±1 フロア・±20 マスの施設が消える（エレベーターと階段は残る）。
- **火災**: ★2 以上でまれに発生する。ある施設から燃え始め、横と上の階に広がる。警備室があれば消火に向かう。`prompt` で「ヘリで消火 $50万」も選べる。一定時間燃えた施設は焼失する。
- **ゴキブリ**: 要清掃のホテル客室が2日放置されると発生する。毎日、隣接する客室（同じ階で隣り合う、または上下で重なる）に広がる。発生中の客室は予約が入らない。パネルの「駆除 $1万」で解消する。
- **住民の苦情**: 評価が bad の、または騒音のあるマンション・オフィス・ホテルが苦情を出す。`message` で通知し（「〇Fの住人: エレベーターが遅すぎる！」など、原因別の文面）、施設に `complaintUntil` を設定して吹き出しを表示する。
- **VIP 来館**: ★4 の VIP 以外の条件がそろい、スイートがあるとき、予告のあと VIP が来館して1泊する。移動時のストレスと清掃状態で判定する。成功すれば★4、失敗なら7日後に再挑戦。
- **結婚式**: ★5 で 100F に大聖堂があると、土日の 11時に新郎新婦と招待客10人がロビーから大聖堂へ向かう。新郎新婦が14時までにストレス 60 未満で着けば TOWER 達成（`tower` イベントを出す）。失敗なら翌週に再挑戦。
- ほかにも本家らしい演出（クリスマスのサンタなど）を足してよい。

## Sim API（`js/sim/tower.js` の `Tower`）

```js
const sim = new Tower();          // 新規ゲーム
sim.step(minutes);                // 時間を進める（内部で 0.25 分刻み）
sim.on(name, fn);                 // 通知の購読
sim.serialize() -> plainObject;   // JSON にできる形
sim.restore(obj);                 // 読み込み（人の状態は時刻に応じて妥当に再構成）
```

### 読み取り用フィールド（render と UI は読むだけ。書き換えない）
- `sim.time`, `sim.day`, `sim.hour`, `sim.minute`, `sim.weekday`（0〜6）, `sim.money`, `sim.pop`, `sim.star`（1〜5）, `sim.tower`（bool）
- `sim.ledger = {income, expense}`（当日分）, `sim.yesterday`（前日分または null）
- `sim.grid[f]`: 長さ `W` の `Int32Array`。0 は空、-1 は空きフロア、正の数は施設 id。h>1 の施設や縦長のエレベーターは占有するすべてのマスに id が入る。
- `sim.objs`: `Map<id, obj>`。施設の共通フィールドは `{id, type, f, x, w, h, occupied, inCount}`。
  - `occupied`: テナントが入居中、ホテルなら宿泊中、商業・サービス施設は常に true。
  - `inCount`: 中にいる人数（室内に人影を描くのに使う）。
  - ホテル: `dirty`（要清掃）, `infested`（ゴキブリ）。
  - `complaintUntil`（この時刻まで吹き出しを出す）, `complaint`（文面）。
  - `burnt`（0〜1、焦げの度合い）。
  - エレベーター（`type` が `'elevator'` または `'express'`）: `{x, w, lo, hi, cars:[{pos, dir, state, pass:[]}], q:{[floor]:{up:[], down:[]}}}`。`pos` はフロアの小数値、`state` は `'idle'|'moving'|'doors'`。
- `sim.evalLevel(o)` -> `'good'|'fair'|'bad'|null`, `sim.isOpen(o)` -> bool（営業時間内か）
- `sim.active`: 移動中の人の `Set`。人は `{id, kind, state, stress, f, x}`。
  - `kind`: `'worker'|'resident'|'guest'|'visitor'|'guard'|'maid'|'vip'|'bride'|'groom'|'weddingGuest'`
  - `state`: `'walk'|'wait'|'ride'|'stairs'`。`ride` の人はカゴの中なので描かない。`wait` の人はエレベーターの待ち列 `q` から描く。
  - `sim.drawPos(p)` -> `{x, f}` または null。x はマスの小数値、f はフロアの小数値で、階段の途中なら中間値になる。
- `sim.fires`: `[{f, x0, x1}]`（燃えている区間）
- `sim.bomb`: null または `{f, x, deadline, searched:Set<f>, found:bool}`
- `sim.effects`: `[{kind:'explosion'|'smoke'|'bells'|'fireworks'|'sparkle', f, x, t0, dur}]`（t0 と dur はゲーム分。sim が期限切れを取り除く）
- `sim.santa`: null または `{x, f}`（クリスマスの演出用。任意）

### 操作
- `sim.check(tool, p)` -> `{ok, reason, cost, ghost}`。実際には何もしない。
- `sim.build(tool, p)` -> 戻り値は `check` と同じ。成功時は建設する。
  - `tool` は `TYPES` のキーまたは `'bulldoze'`。
  - `p = {f, x}`。横ドラッグのツール（floor・lobby・bulldoze）は `x2` も渡す。縦ドラッグのツール（elevator・express）は `f2` も渡す。クリックで置くツールの `x` は左端のマス。
  - `ghost`: 単一フロアの施設は `{x, w, f, h}`、エレベーターは `{x, w, lo, hi}`。UI はこれを renderer にそのまま渡す。
- `sim.objAt(f, x)` -> obj または null
- `sim.describe(o)` -> `{title, subtitle, stats:[[label, value]], level, actions:[{id, label, cost, enabled, danger}]}`
- `sim.act(o, actionId)` -> `{ok, reason}`。アクションは `addCar`、`removeCar`、`extendUp`、`extendDown`、`exterminate`、`remove` など。
- `sim.answer(promptId, value)`: `prompt` への回答。
- `sim.starProgress()` -> `{star, next, reqs:[{label, done}]}`

### 通知（`sim.on`）
- `'message'`: `{text, kind:'info'|'good'|'bad'|'money'|'star'|'event'|'complaint', f?, x?}`。f と x があれば、UI はその場所へジャンプできる。
- `'prompt'`: `{id, kind:'bomb'|'fire'|'vip'|'wedding'|..., title, text, choices:[{label, value}]}`。UI はモーダルを出して一時停止し、`sim.answer` で答える。
- `'star'`: `{star}`
- `'tower'`: `{}`（エンディング）
- `'sound'`: `{name}`。name は `'cash'|'ding'|'build'|'bulldoze'|'error'|'boom'|'fire'|'alarm'|'bells'|'fanfare'|'roach'|'complaint'`

## Renderer API（`js/render/renderer.js`）

```js
const r = new Renderer(canvas, sim);
r.resize(cssWidth, cssHeight);      // devicePixelRatio の処理は renderer の中で行う
r.render(view);                     // 毎フレーム呼ぶ
// view = { cam:{x,y,zoom}, ghost:{...sim の ghost, ok:bool, label?:string} | null,
//          selectedId: number|null, hover:{f,x}|null, nowMs: performance.now() }
r.setSim(sim);                      // ロード時などに差し替える
```
- 本家風のピクセルアート。横から見た断面図で、黒い輪郭線、室内の家具と人影、昼夜で変わる空、夜の窓明かり、雲、地層の見える地下を描く。
- 評価は小さなインジケータで示し、ストレスは人の色で示す。苦情は吹き出し、ゴキブリ・火災・爆発・爆弾捜索中の表示、結婚式の演出も描く。
- フロア番号のラベル（1F、B1F、…）を左端に描く。
- 画面外は描かない（カリング）。100F・数千人の規模でもスマホで 60fps 近くを目指す。生成したスプライトはオフスクリーンキャンバスにキャッシュする。

## UI（`index.html`, `js/main.js`, `js/ui/*`）
- タイトル画面（新規・続きから）、上部 HUD（★、資金、人口、日付・曜日・時刻、速度）、施設ツールバー（カテゴリ別、コストと★によるロック表示）、情報パネル（`describe` と `act`）、トースト通知、事件のモーダル、★の昇格演出、TOWER 達成のエンディング。
- 入力: PC はドラッグで建設、右クリックドラッグまたはスペース＋ドラッグでスクロール、ホイールでスクロール、Ctrl＋ホイールでズーム、ショートカットキー。スマホは1本指で建設またはパン、2本指でピンチズームとパン。小さい施設は配置プレビューをもう一度タップして確定する。
- オートセーブ（ゲーム内の1日ごと）と手動セーブ・ロード。データ破損に強くし、try/catch で囲む。
- 効果音は WebAudio で合成する（音声ファイルなし）。ミュートボタンを付ける。

# v2 追加仕様（フィードバック対応）

この節は上の内容より優先する。対応するフィードバックは `fb.md` に書いてある。

## 1. 横幅を3倍に
`W = 480` に変更した（2^5・3・5 で約数が多い）。全施設の幅を W の約数にしたので、横幅いっぱいに同じ施設を並べてもマスが余らない（office 10、cinema 32、partyHall 30、medical 24、recycling 24 に変更）。古いセーブは横幅が150なので、sim の `restore` が右側を空にして読み込む。幅が変わった施設の古いデータは、新しい幅で置けるなら置き直し、置けなければ読み飛ばす。

## 2. 移動手段の層を分ける
- `sim.grid[f]` には**フロアと施設だけ**を入れる（0 は空、-1 は空きフロア、正の数は施設 id）。移動手段の id は入れない。
- 新しく `sim.tgrid[f]`（長さ `W` の `Int32Array`）を設ける。移動手段（`TRANSPORT_TYPES`）の id と、エレベーターの機械室・ピットのマスが入る。
- 移動手段は施設と重ねて置ける。移動手段どうしは重ねられない（`tgrid` が 0 のマスにだけ置ける）。
- 移動手段の各マスには構造が必要（`grid` が 0 以外）。例外は機械室とピットで、空中や地中にも置ける。
- 支えの判定は `grid` だけで行う。移動手段は支えにならない。
- `sim.objAt(f, x)` は施設を返す。新しく `sim.transportAt(f, x)` を追加する。UI の「調べる」と「撤去」は移動手段を優先する。
- 描画は施設の上に移動手段を重ねる。シャフトの後ろの施設は隠れてよい。

## 3. エレベーターの機械室とピット
- 通常・急行エレベーターは、hi+1 階に機械室、lo-1 階にピットを持つ。どちらも `tgrid` 上でエレベーターの id を持つ。
- 範囲 `MIN_F`〜`MAX_F` の外になる場合は保存しない（render は描く）。
- ghost の `{x, w, lo, hi}` でも、render は機械室とピットを含めて描く。

## 4. エレベーターの拡張
- **ドラッグで伸縮:** `sim.check/build('resizeElevator', {id, lo, hi})` で範囲を変える。返す ghost はエレベーターと同じ形。UI は、選択中のエレベーター（または調べるツールでシャフトの上端・下端）をドラッグして伸縮できるようにする。
- **設定:** `e.config = { skip: number[], standby: 'none'|'lobby'|'spread', rush: bool, speed: 1|2, door: 'short'|'normal'|'long' }`
  - `skip`: 止まらない階
  - `standby`: 待機中のカゴの置き場所
  - `rush`: 朝はロビーへ、夕方は上階へ空のカゴを回す
  - `speed`: 2 は高速モーター。カゴの維持費が2倍
  - `door`: ドアの開閉時間
  - 変更は `sim.setElevatorConfig(e, patch)` -> `{ok, reason}` で行う。
  - 急行の `skip` に入れられるのは、ロビー階と地下階だけ。
- **動きのリアルさ:** カゴは速度 `car.v` を持ち、加速・定速・減速して止まる。最高速度は急行が速い。`car.v` は render も読める。
- **固まる不具合:** 「待ちがあるのに全カゴが idle のまま」「カゴが同じ目標を取り合う」などを再現テストで見つけて直す。不変条件「待ちがあれば、ある程度の時間内に必ずどこかのカゴが向かう」をテストで保証する。

## 5. テナントの個性
- 施設は `o.variant`（`VARIANTS[type]` の添字）と `o.brand`（店名・社名、日本語）を持つ。オフィスとマンションは入居のたびにランダムに引き直す。商業施設とホテルは建てたときに決まる。
- render は variant ごとに内装・看板・配色を描き分ける。さらに `o.id` を種にした小さなランダム差（家具の配置や色）も加え、同じ variant でも画一的に見えないようにする。
- `describe` の title か subtitle に brand を出す。

## 6. 破壊されたテナント
- 爆発で消える範囲の施設と、火災で焼け落ちた施設は、消えずに `o.destroyed = 'bomb'|'fire'` になる。
- 破壊された施設は使えない。人は来ず、収入もなく、入居もしない。撤去して建て直すしかない。
- render は瓦礫・焼け跡を描く。`describe` は撤去を促す。

## 7. 評価の内訳
- sim は施設ごとにストレスの原因を集計する（エレベーター待ち、階段、移動距離、混雑、騒音、未清掃、行けない、など）。
- `describe(o)` に `reasons: [{label, level:'good'|'fair'|'bad'}]` を追加し、stats にも具体的な数値（「平均待ち 12分」など）を出す。

## 8. 消防ヘリ
- ヘリ消火を選ぶと `sim.heli = {x, f, phase:'in'|'spray'|'out', targetX, targetF}` になる。x と f は小数。sim が毎 tick 位置を更新する。
- ヘリは画面外から飛んで来て、散水し、去る。消火はヘリが着いた後に行う。
- render はヘリ・ローター・散水を描く。UI はヘリの音を出す。

## 9. 一括コピー
- `sim.blueprint({f1, x1, f2, x2})` -> `{w, h, ops:[{tool, p}]}`。範囲内のフロアのまとまり・施設・移動手段を、建てられる順（下から上、地下は上から下、移動手段は最後）に並べた建設手順を返す。座標は範囲の左下を (f=0, x=0) とした相対値。
- `sim.checkBatch(ops)` / `sim.buildBatch(ops)` -> `{ok, cost, reason, failedIndex, ghosts:[...]}`。全部建つか、何も建たないかのどちらか（アトミック）。
- UI の「コピー」ツール: ドラッグで範囲を選び、貼り付け位置にマウスまたは指を合わせると、全体のゴーストが出る。クリックで建てる（スマホは確定ボタン）。
- renderer の view に `ghosts: [...]`（複数のゴースト）を追加する。

## 10. 演出と UI
- **飛行機:** render が、時刻を種にして決定的に、ときどき空に飛行機を飛ばす。昼は機体、夜は点滅灯。
- **夜の早送り:** UI は、深夜（0〜6時）で事件中でなければ、現在の速度にさらに×4 をかける。HUD に「🌙 早送り中」と出す。
- **事件時は等速に:** UI は、prompt または kind が `'event'` の message を受けたら、速度を×1 に戻す。
- **調べるツールのカーソル:** 虫眼鏡にする（SVG の data URI）。撤去はブルドーザー、コピーは専用のカーソル。
- **効果音を増やす:** エレベーターの走行音（加速・減速に合わせて音程が変わる）とドアのチャイム、オフィスの環境音（タイピングと電話）、ファストフードの雑談と調理音、ロビーのざわめきなど。画面に映っている範囲・時間帯・人の量に応じて、WebAudio で合成した環境音を流す。音量は控えめにし、設定でオン・オフできるようにする。

## 11. 追加フィードバック
- **全画面表示:** UI が HUD とメニューから切り替えられるようにする（対応済み）。
- **非常階段（飾り）:** render が、建物の左右の外壁に沿って非常階段を描く。構造のある各フロアの左端と右端の外側に、ジグザグの階段と踊り場を付ける。sim は何もしない。人も使わない。
- **急行エレベーターの停止階:** 急行の `config.skip` は任意の階を指定できる。既定値は「ロビー階と地下階以外のすべて」で、急行が止まるのはロビー階と地下階になる。止まる階を増やすと、その階にも停止する。止まる階が2つ未満になる変更は拒否する。UI の設定画面では、範囲内の全フロアを切り替えられるようにする。

## 12. 建設中の演出とごみ収集室
- **建設中:** 建てた施設と移動手段は、すぐには使えず `o.constructUntil`（ゲーム時刻）まで工事中になる。工期は大きさに応じて 30〜240 ゲーム分（フロアだけなら工事なし）。工事中は人が使わず、入居もせず、収入もない。
  - render は足場・防音シート・クレーン・作業員・火花などで工事中を描き、`(time - 開始) / 工期` の進み具合に応じて仕上がっていく様子を見せる。進み具合は sim が `o.constructStart` と `o.constructUntil` で渡す。
  - UI は工事の音（トンカチ、ドリル）を、画面に映っているときに控えめに鳴らす。sim は完成時に `'sound' {name:'built'}` を出す。
  - restore では工事の続きを再開する。
- **ごみ収集室（`garbage`、幅8、★1）:** 上下5フロア（`range`）のテナントのごみを集める。
  - テナントは毎日ごみを出し、ごみ収集室の `o.fill`（0〜1）が増える。毎朝5時に回収業者が回収し、1袋あたりの料金を払う。地下にリサイクルセンターがあれば、料金は安くなる。
  - 範囲内にごみ収集室が無い施設、または満杯（fill≥1）の収集室の範囲の施設は、評価の内訳に「ごみが溜まっている」が付き、ストレスが加算される。苦情の原因にもなる。
  - render は fill に応じて、ごみ袋の山・ごみ箱・作業員を描く。

## 13. レビュー対応: ごみ集積所と駐車場（§12 のごみ収集室を置き換える）
- **ごみ集積所（`garbage`）:** 地下2フロア分（w16・h2・`only:'basement'`）。距離に関係なく、ビル全体のごみをすべての集積所でまとめて受け持つ（`range` は廃止）。
  - テナントのごみは、集積所の合計容量（`capacity` × 室数）に対して溜まっていく。各室の `o.fill`（0〜1）と `o.bags`（袋の数）は、溜まった量を室ごとに割り振った値。
  - 毎朝、ごみ収集車が来て回収する。4:30〜5:30 のあいだ、各室に `o.truck = {phase:'in'|'load'|'out', t:0..1}` を設定する（それ以外の時刻は null）。'load' の間に `bags` が減っていき、回収料金は袋の数に比例する。
  - 集積所が1つも無い、または満杯（fill≥1）のときは、ビル全体のテナントの評価内訳に「ごみが溜まっている」が付き、ストレスが加算されて苦情の原因にもなる。
  - 古いセーブにある1フロアの `garbage` は、置けるなら地下に移し、置けなければ読み飛ばす。
  - render は、地下2フロア分の集積所（荷捌き場・スロープ・ごみ置き場）を描き、袋の数に比例してごみ袋を積む。収集車が入ってきて、作業員が袋を積み込み、出ていくまでを描く。
- **駐車場（`parking`）:** 地下のみ（w24・h1・★2で解放）。1室あたり `spaces` 台。
  - ★3以上になると、入居者の一部が車を持つ。オフィスは約3割、マンションは約4割、スイートは全室。入居時に `o.needsParking`（台数）を決める。
  - 必要台数の合計が駐車場の台数を超えると、足りない分のテナントの評価内訳に「駐車場がない」が付き、ストレスが加算されて苦情の原因にもなる。割り当ては先に入居した順。
  - 各駐車場の `o.used`（使用台数）を render が読んで車を並べる。`describe` には「駐車場 使用 N/M 台」「不足 N 台」を出す。

## 14. フィードバック対応（第4弾）
- **徒歩の速さ（sim）:** 1マス＝2m（オフィス幅10マス＝20m）とし、歩く速さは 80m/分＝**40マス/ゲーム分**とする。実時間モードで現実に近い速さになる。評価・経路選択・バランスはこの速さで測り直す。
- **ごみとリサイクルの一本化（constants はリードが変更済み）:** `recycling` 型は廃止し、`garbage` を「ごみ・リサイクルセンター」（w24・h2・地下・★1・capacity 600）にする。
  - ★4 の条件「リサイクルセンター」は「ごみ・リサイクルセンターがあり、ごみが溢れていない」に置き換える。回収料金の割引は廃止し、料金を見直す。
  - 古いセーブの `recycling` は、同じ場所に `garbage` として置き直す。置けなければ読み飛ばす。古い `garbage`（w16）も、置けるなら w24 で置き直す。
  - render は、分別ライン（コンベア、色分けされたリサイクル箱）を持つ一つの施設として描き直す。
- **フロアの切れ目（sim）:** 人は、構造のあるマスが連続している区間（同じ階の「区画」）の中だけを歩く。経路探索は (階, 区画) を節点にし、移動手段はそれが触れる区画どうしをつなぐ。区画をまたげない行き先は「行けない」扱いにする。`drawPos` も区画の外に出ない。
- **退去で施設が消えるバグの確認（sim）:** 退去・買い戻し・ホテルのチェックアウトなどで、施設オブジェクトが撤去・破壊されうる経路がないかをコードとテストで確かめる。見つかれば直し、再発防止のテストを付ける。
- **エレベーターの延長でフロアも作る（sim）:** `resizeElevator` で、延長先の階のシャフトのマスにフロアが無い場合、支えがあればシャフトの幅だけ自動でフロアを作る（費用はフロア代を加算）。支えが無ければ従来どおり不可にする。
- **人のプロフィール:**
  - **sim:** 人には `name`（日本語の氏名）、`age`、`job`（勤め先・肩書き・住まいなどを kind に応じて）を安定した乱数で付ける（保存されなくてよいが、同じ人には同じ値）。
  - **sim:** `sim.personAt(f, x, r=1)` は、そのフロアの x 付近にいる人を返す（移動中・待ち行列。室内の人は対象外）。`sim.describePerson(p)` は `{title, subtitle, stats:[[label, value]], mood}` を返す。中身は名前、年齢、職業・所属（社名・店名）、住まいまたは勤め先、いまの行動と行き先、ストレス、今日の予定。
  - **UI:** 調べるツールで人をクリック・タップするとプロフィールを表示する。人のほうを施設より優先する。選択中は `view.selectedPerson = p` を渡し、画面外に出たら追いかけるボタンを出す。
  - **render:** 選択中の人を強調表示する（枠や矢印、頭上にマーカー）。
- **評価の一括表示:**
  - **UI:** HUD かツールバーに「評価」ボタンを置き、押すと `view.overlay = 'eval'` を切り替える。凡例も出す。
  - **render:** overlay が `'eval'` のとき、施設ごとに `sim.evalLevel(o)` の色（good 青、fair 黄、bad 赤、空室・評価なしは灰）を網掛け（斜線ハッチ＋半透明）で重ねる。工事中・破壊済みも区別して描く。
- **ホテルのレビュー（sim と UI）:**
  - **sim:** ホテルの客室は、チェックアウトのたびにレビュー `{stars:1..5, text, day, name}` を `o.reviews` に足す（最新20件まで、保存する）。星の数は、移動時のストレス、清掃状態、ゴキブリ、騒音、エレベーター待ちから決める。一言コメントは原因に合わせた日本語の定型文を複数から選ぶ。
  - **sim:** `describe` に平均の★と最新3件を入れ、`describe().reviews` も返す。
  - **UI:** パネルで★とコメントを読みやすく表示する（全件を開ける）。
- **コピーの改善（UI 主体、sim と render は補助）:**
  - **貼り付けの横位置:** 既定ではコピー元と同じ x に固定し、上下だけ動かす。PC は Shift を押している間、スマホは「横も動かす」トグルで自由に動かせる。
  - **施設ごとに選ぶ:** コピーツールで施設をタップ・クリックするたびに選択を切り替える（範囲ドラッグとの併用も可）。選択中の施設は `view.marked = Set<id>` で渡す。
  - **render:** marked の施設に、スマホの複数選択のようなチェックマークのバッジと薄い枠を描く。
  - **sim:** `sim.blueprintOf(ids)` を追加する。選ばれた施設と、それを支えるのに必要な最小限のフロアから、`blueprint` と同じ形を返す。
- **建設の枠をつかむ位置（UI）:** 配置プレビューをドラッグで動かすとき、指やマウスが触れた場所と枠の相対位置を保つ。枠の端をつかんでも、枠の中心が指に飛ばない。
- **スマホ（UI）:**
  - **横向き:** 横向きのレイアウトを、実機サイズ（844×390、932×430 など）、セーフエリア（ノッチ・ホームバー）、アドレスバーの伸び縮み（100dvh）に合わせて見直す。
  - **iPhone の Safari:** Fullscreen API に対応していないので、代わりの手段を用意する。全画面ボタンを押したら「ホーム画面に追加」すると全画面で遊べることを案内し、PWA の設定（`apple-mobile-web-app-capable`、`display: fullscreen` / `standalone`、`viewport-fit=cover`）を整える。ホーム画面から起動したときは、ブラウザの UI なしで動くようにする。
- **【まだ対応しない】** 周辺環境による戦略の変化。

## 15. 連絡通路（`bridge`）
- 地上（f≥1）にだけ、横ドラッグで架ける橋。★2で解放、1マス $3,000。
- **下に支えが無くても建てられる。** ただし、少なくとも片方の端が同じ階の既存の構造（フロア・施設・ロビー）に接していること。何にも接していない宙に浮いた橋は建てられない。
- 橋のマスは「歩ける床」として扱う。同じ階の区画をつなぐので、離れた棟どうしや、フロアの切れ目を渡れるようになる。
- 橋の上には施設を置けない。また、橋は上の階を支えない（橋の上の階は橋を支えにできない）。移動手段（階段・エレベーター）を橋に重ねて置くこともできない。
- `grid` 上では、橋はオブジェクト（`type:'bridge'`, `f`, `x`, `w`）として id を持つ。撤去は橋ごと。
- render は、鉄骨トラスとガラス張りの通路として描き、夜は通路の照明を付ける。下に何も無い空間でも自然に見えるようにする。人は橋の上を歩く。
